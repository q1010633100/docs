---
title: Webhook 事件
description: 验证事件签名并可靠地处理异步通知
---

当订单状态变化时，示例服务会向预先配置的 HTTPS 地址发送事件通知。

## 事件结构

```json
{
  "id": "evt_01J5K9M4R8T2W7",
  "type": "order.paid",
  "created_at": "2026-11-02T10:00:00Z",
  "data": {
    "order_id": "ord_01J5K7N3M8Q2X4V6",
    "status": "paid"
  }
}
```

## 处理流程

<Steps>
  <Step title="读取原始请求体">
    签名校验必须使用未经 JSON 反序列化或重新格式化的原始字节。
  </Step>
  <Step title="验证签名和时间戳">
    使用 Webhook 独立密钥验证签名，并拒绝时间戳过旧的请求，降低重放攻击风险。
  </Step>
  <Step title="持久化事件 ID">
    使用事件 ID 去重，确保同一事件重复投递时不会重复执行副作用。
  </Step>
  <Step title="快速返回 2xx">
    接收并持久化事件后尽快响应，耗时任务应交给后台队列处理。
  </Step>
</Steps>

## 重试策略

接收端应实现指数退避和最大重试次数。若订单最终状态依赖事件顺序，还应保存事件创建时间，并忽略已经过期的事件。
